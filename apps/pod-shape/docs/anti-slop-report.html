Shape Board · design system review

What makes our UI look AI-made, and what to change

I read 5 reference sites and checked the current design system v1 against them. Below: what I learned, 6 proposed changes, and new rules for agents. Nothing is changed yet. Pick an option on the card in the thread.

Honest verdict on v1

v1 is clean and consistent, but it looks like the default shadcn app. That is the main "AI slop" signal in it.

  • Inter + zinc gray + one bright accent is the shadcn default. Thousands of AI-built apps look exactly like this.
  • The sparkles icon on "Generate issues" is the most common AI cliché in UI today. I used it. It should go.
  • Nothing in the UI comes from the product's own world. The logo has a strong idea (a branch with an orange node), but the UI does not use it anywhere.
  • Good parts to keep: one accent color, status = icon + label, dense 13px type, borders instead of shadows, the locked token list.

What I learned from the 5 sites

Knowns UI

ui.knowns.dev

React + Tailwind kit "for AI products". Copies source into your repo with the shadcn CLI. 76 components, 176 blocks. Free part is MIT, Pro is paid.

Useful pieces for us: Tool call card, Approval prompt, Chat composer, Stepper, Inline diff.

Use as idea source Borrow 1–2 patterns. Do not install the kit: it brings its own look, so the app would look like every other app built on it.

Realtime Colors

realtimecolors.com

Preview a palette on a real page. Five roles: text, background, primary, secondary, accent. Contrast check per pair (fail / AA / AAA). Exports CSS, Tailwind, OKLCH.

Its guidance: 3 colors are usually enough, rarely more than 6, keep ratios near 60-30-10.

Adopt Use it to test our palette, and add the 60-30-10 rule and AA contrast as written rules.

Haikei

haikei.app

Generator for SVG backgrounds: layered waves, blobs, peaks, steps, low-poly grids, gradients. Exports SVG / PNG.

Mostly avoid Blobs and waves are a top AI-slop look, and a dense tool does not need them. Allow one exception only: a quiet pattern made from our own logo shape, in empty states.

Lucide

lucide.dev

The icon set we already use (lucide-react, ISC licence, about 2,000 icons). Default is 24px with 2px stroke. Stroke can be changed per icon.

Keep, add rules One fixed icon per meaning, a fixed stroke per size, and no icons used only as decoration.

Proposed changes

1

UI font: Inter → IBM Plex Sans

NowInter 13px. Default of shadcn, Vercel, Linear clones.
ProposedIBM Plex Sans, bundled with @fontsource/ibm-plex-sans (SIL Open Font License). Keep JetBrains Mono for ids and paths.

Updated in v1.2: the user chose IBM Plex Sans after a side-by-side test. It reads well at small sizes, so the app keeps its density and loses the "default" feel, and its licence (SIL OFL) is clear.

2

Neutrals: cold zinc → gray with a small warm tint toward the logo orange

Now · darkTailwind zinc, cold blue-gray
Proposed · darkSame lightness, tiny warm tint

Grays with a slight lean toward the accent look chosen on purpose. Pure zinc is Tailwind's default. I checked contrast: all text tokens still pass AA (4.5:1) on every surface in both themes. The logo files and #F97316 do not change.

3

Signature detail: the branch from the logo

Draw the overview tree with rounded branch lines like the logo, and use the orange node only for "you are here / running now". The same line style goes into the pipeline steps (Prototype → Grill → Generate → Issues). This is the one bold detail. Everything else stays quiet.

4

Icons: fixed map and fixed stroke

Now16px, stroke 1.75. Any lucide icon allowed. sparkles on Generate.
ProposedOne file icons.ts maps meaning → icon. 16px stroke 1.75, 14px stroke 1.5, 12px stroke 1.5. Generate uses git-branch-plus.

Agents pick random icons when they can. A single map makes the same idea always use the same icon. Rule: an icon must carry meaning. No icon in front of every heading.

5

Color budget: 60-30-10, written as a rule

Now"Max one primary button per view."
ProposedAbout 60% bg, 30% surfaces and text, 10% or less accent. Status colors only inside badges, dots and the status bar. Never as backgrounds of whole cards or rows.

From Realtime Colors. Easy for an agent to check, and it stops the "everything is colorful" look.

6

Two new parts from Knowns UI ideas (optional)

NowNo way to show what a background Claude session is doing.
ProposedPipelineSteps (Prototype → Grill → Generate → Issues) and RunLog (tool-call style rows for a running session). Built with our own tokens.

You said a grill is a Claude Code background session with history. These two parts show that clearly. I copy the idea, not the code or the look.

New "anti-slop" rules for agents

These go into DESIGN_SYSTEM.md §0 and the CLAUDE.md snippet. Each is easy to check in a diff.

✕No gradients on text, buttons or backgrounds. No purple-blue anything.
✕No glass, blur or glow: no backdrop-blur, no colored shadows.
✕No sparkles / magic-wand icons for AI. Say what happens instead.
✕No emoji in UI text, headings or empty states.
✕No card inside a card, and no colored left border on cards.
✕No blobs, waves or decorative backgrounds. Only the logo-branch pattern in EmptyState.
✕No centered hero layouts inside the app. Content is left-aligned.
✕No filler copy: "Unlock", "Seamlessly", "Supercharge", "AI-powered". Use plain verbs and real numbers.
✕No lorem ipsum or fake round numbers in mocks. Use realistic repo, issue and branch names.
✕No new font, icon set or UI kit (including Knowns UI) without asking.
What I could not check
  • Knowns UI's exact visual style (fonts, radius). I only read its text pages.
  • Haikei licence terms, and the Lucide accessibility page.
